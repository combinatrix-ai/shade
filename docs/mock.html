Shade · macOS menu panel · design proposal

Intent is a switch.
Activity is a state.

The current panel merges “what the user asked for” with “what Shade is doing right now”, so the battery and disabled cases read as a dead end. This redesign keeps one 320 pt panel but always answers three questions at a glance: is Shade on? · is it actually running? · what do I press next?

1 · State model

One switch, three runtime states, one blocker

Every screen below is produced by the same four inputs: user intent, power source, the Only on power adapter setting, and the runtime phase. Nothing else is hidden in the UI.

Intent — the switch in the header

The switch means “I want Shade running”, nothing more. It stays on while Shade is paused on battery, because the user never asked for it to stop. It is only ever off because the user turned it off.

Activity — the ON/OFF pill + status line

Green pill = assertions held, display managed. Amber outlined pill = intent kept, but Shade is not running. Grey pill = nothing held. The line beside it says the reason in plain words.

Blocker — an actionable card, never a bare grey button

When the power policy prevents starting, the panel names the setting that is blocking it and offers the one-tap fix. A disabled control without a stated cause is the bug this redesign fixes.

意図と実状態の分離：スイッチは「ユーザーの意思」だけを表し、実際に動いているかはピル（ON緑／ON琥珀＝一時停止／OFF灰）と状態行で表す。バッテリー時の不可状態は「無効化されたボタン」ではなく、原因の設定名と 1 タップの解決策を示すカードとして提示する。

    4 · Status icon

    One icon, three gestures

    Appearance

    The icon is a filled half-circle. When Shade is not running it renders dimmed (macOS appearsDisabled); while paused it is dimmed too, because nothing is being held — the panel is where intent lives.

    • Running — full contrast, tooltip “Shade · Keeping Mac awake”
    • Paused — dimmed, tooltip “Shade · Paused, waiting for power”
    • Off — dimmed, tooltip “Shade · Off”
    • Unavailable — dimmed, tooltip “Shade · Needs a power adapter”
    Gestures
    GestureResult
    Single clickOpens the panel, after the system double-click interval so a double never flashes it.
    Double clickToggles intent without opening the panel.
    Right clickToggles intent without opening the panel.

    If a toggle attempt is blocked by the power policy, the panel opens on the blocked screen instead of failing silently.proposed

    6 · Proposed behavior changes

    挙動変更の提案（実装は未承認）

    Everything not listed here is a visual restatement of the shipped behavior in AppModel.swift / Views.swift. The items below change what the app does and need approval before implementation.

    1. “Allow on Battery” button inside the blocked cardbehavior

      ブロック中のパネルから onlyOnPowerAdapter を直接 false にし、そのまま起動する。現行は Settings を開いてトグルを探す必要があり、無効理由と解決策が分離している。書き込む設定名をカード本文に明示するため、意図しない変更にはならない想定。

    2. Paused keeps the switch visibly ON, in ambervisual + semantics

      現行も isOn || waitingForPower でスイッチは ON に見えるが、緑のまま「動作中」と区別がつかない。琥珀＋アウトラインのピルで「意図は保持、実行はしていない」を明示する。ロジック変更なし、表示のみ。

    3. Countdown shows progress against the chosen delayvisual

      残り時間だけでなく「1 min のうち」の帯を出す。reserve() によるカウントダウン再武装が上限を超えないことが目で確認でき、「思ったより長い／短い」という混乱を防ぐ。

    4. Blocked toggle from the status icon opens the panelbehavior

      ダブル／右クリックでの起動がパワーポリシーで拒否された場合、無反応ではなくブロック画面を開く。

    5. Inline shortcut validation and conflict textcopy

      修飾キー不足は「Add ⌘, ⌃, or ⌥」、他アプリとの競合は競合したキー表記を含む一文をフィールド直下に赤で出す。現行は登録失敗を汎用エラー行で伝えている。

    6. Settings marks the setting that is blocking right nowvisual

      バッテリー動作中で onlyOnPowerAdapter が ON の場合、その行に「ON BATTERY」バッジを付ける。設定画面と主画面の因果を結ぶ。

    Unchanged, deliberately

    320 pt 幅・単一パネル内の Settings/Tutorial・手動 OFF 起動・8 時間上限・ロック設定を触らない方針・外部ディスプレイ非対応・「これはセキュリティではない」という位置づけ。チュートリアル下部の赤い 2 行は仕様どおり最下部に固定し、「Don’t show on startup」は初期状態で未チェック。
